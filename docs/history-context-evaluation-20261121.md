## 实施与撤回范围

1. 大结果投影：成功的长 Bash/Read 等返回值，以同一 Worker 意图、调用 ID、工具名及 SHA-256 匹配唯一持久化审计记录，替换为 3000 字符首尾片段与 context_get 读取引用；补充已有 context_search 的定位范围。错误、权限不足、记录缺失或匹配歧义时保留原文。
2. 阶段检查点：压力触发结构化摘要，保留成对近期调用和原始审计。独立复测发现目标漂移，先撤回这一部分。
3. 再次单独测试大结果投影，两组恢复相同的原压缩器，得到上表结果；仍出现精确证据遗漏，因此也撤回。

开发阶段还发现向模型展示内部 SHA-256 会诱导其用校验信息替代任务证据，已在候选复测前去掉；去掉后仍未解决全部质量回退，未据此宣称优化成功。

## 方法和边界

- 四个成对案例：大结果回读 2 组，长历史经过原压缩器后继续执行 2 组；采用不同合成种子，双方使用相同证据和工具能力。
- 真实模型处理隔离 PostgreSQL 中的合成执行记录，不执行 Bash 命令，不使用生产任务证据，不是任务 160 的完整重跑。
- 两组均可使用 context_search 和 context_get。验收包含精确证据值、已经完成的写入回执，以及只读下一步。
- 压力场景测试窗口 64000，未修改生产窗口。统计包括摘要和后续回读模型请求。
- 重复读取按工具名称及规范化参数完全相同统计，不表示不存在片段重叠读取。
- 测试进程 PASS 只表示流程运行完毕；业务成功必须检查每条记录的 success。样本较小，不能据此声称普遍收益；已观察到的质量回退足以否决此次候选。
