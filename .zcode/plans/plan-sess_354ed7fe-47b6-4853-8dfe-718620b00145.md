# 方案 B：curl/wget 默认浏览器 UA（curlrc/wgetrc + Bash 环境注入）

## 原理

curl 读取 `$CURL_HOME/.curlrc`、wget 读取 `$WGETRC` 指向的配置文件；命令行 `-A/--user-agent` 优先于配置文件——即模型显式指定 UA 时仍可覆盖。与代理无关，**捕获关闭时同样生效**；只作用于 curl/wget，不碰其它工具。

## 一、配置文件（server 侧）

1. Manager 启动时（NewManager，数据目录已知）幂等写两个文件到 `<data>/tool-http/`：
   - `.curlrc`：`user-agent = "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/140.0.0.0 Safari/537.36"`（导出常量 `DefaultToolUserAgent`，供测试与后续设置化复用）
   - `wgetrc`：`user_agent = <同一 UA>`
   - 已存在则跳过（不覆盖用户手工修改）。

## 二、环境注入（agent 侧）

2. agent 包新增一次性配置入口 `agent.ConfigureToolUA(curlHome, wgetRC string)`（进程级工具默认值，模式与 traffic 录制开关一致），`proxyEnv`（agent/worker.go:229）在构建 Bash env 时追加 `CURL_HOME=<dir>` 与 `WGETRC=<dir>/wgetrc`。
3. **关键行为变更**：`proxyEnv` 当前在 `proxyAddr == ""` 时直接返回 nil（捕获关闭+无全局代理 → 无任何注入）；改为"代理为空但 UA 配置存在"时仍返回 UA 两项——这正是方案 B 相对方案 A 的价值点。同步更新函数注释。
4. NewManager 写完文件后调用 `agent.ConfigureToolUA(...)`。四个调用点（worker.go:560 / planner.go:490 / mainagent.go:179 / chat.go:163）无需改动，自动生效。

## 三、边界与核实（实现时确认）

5. 核实 harness 对 `BashEnv` 的消费是"追加到 os.Environ"而非替换（third_party/norma/harness/tools.go:133）。
6. 边界说明（不扩范围）：Python requests 等 UA 不在本次范围（后续可用 sitecustomize）；交互式 shell 会话若有独立 env 构造点，顺带核实是否同样注入（有钩子就带上，没有就记为已知边界）。
7. 不影响 `CURL_CA_BUNDLE` 等 CA 变量（CURL_HOME 只影响启动配置读取）。

## 四、测试

8. 单元：`proxyEnv` 三态——代理+CA+UA 全有 / 仅 UA（捕获关闭路径，断言不再返回 nil）/ 全无；文件写入幂等与内容断言。
9. e2e（有说服力的一步）：httptest 起本地服务，`exec.LookPath("curl")` 存在时以 `CURL_HOME` 环境跑真实 curl 请求，断言服务端收到的 User-Agent 是浏览器 UA；`-A` 显式覆盖优先级同场验证。curl 缺失则 skip。wget 同理可选（本机通常有）。
10. 全量回归：`go build ./...`、`go vet`、`go test -p 1 ./agent/ ./server/`（及 db/guard/traffic 快跑）；CHANGELOG Unreleased 增加条目（说明默认 UA、`-A` 可覆盖、文件位置与"已存在不覆盖"语义）。
